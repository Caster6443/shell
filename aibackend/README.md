# Shell 共用 AI 后端

状态：2026-10-21 首版。设置入口：Nexus → AI 服务。默认 AI 与软件描述自动翻译均关闭，不导入旧 aichat 或其他应用密钥。

## 配置

新建服务，填写名称、接口类型、Base URL、API Key，选择存储方式后保存。
Base URL 是 API 根地址，保留版本路径，不包含 `/chat/completions` 等具体端点：

- OpenAI 兼容：例如 `https://api.deepseek.com/v1`；调用 `/models` 和 `/chat/completions`。
- Gemini 原生：`https://generativelanguage.googleapis.com/v1beta`。
- Anthropic 原生：`https://api.anthropic.com/v1`。
- 本地 OpenAI 兼容：例如 `http://127.0.0.1:11434/v1`，允许空密钥。

开启 AI 服务后可获取模型列表；保存时可自动获取。已有服务选择模型后立即保存，手填模型 ID 在结束编辑时保存；测试模型成功也会保存模型选择。新服务先保存连接配置。
获取列表只做查询；“测试模型”会发送一次短生成请求。模型列表不证明生成、多模态或工具能力。
目前为非流式文本接口；OpenAI 兼容不代表所有服务/模型参数完全兼容，Responses、图片、工具调用、自动探测能力不在首版范围。
未内置价格，不将 token 统计视为金额。推理模型可能先消耗输出预算再返回正文，需调整上限或使用适合短文本的模型。

多个服务共享一份默认服务选择，模型保存在各服务配置里。更改接口类型/地址或凭据存储方式时，已有密钥不会自动移交新绑定，必须重新输入。

## 存储与凭据

- 非密钥配置：`$XDG_CONFIG_HOME/caelestia-ai/profiles.json`（缺省 `~/.config/caelestia-ai/`）。
- 默认密钥存储：系统 Secret Service，通过 `secret-tool` stdin 写入；每个服务 UUID、接口类型及地址绑定独立凭据。
- 显式备选“本机私有文件”：`$XDG_DATA_HOME/caelestia-ai/credentials/<UUID>-<地址绑定哈希>.json`；目录 0700、文件 0600，**是本机明文，非加密保险箱**。
- 用量与翻译缓存：`$XDG_STATE_HOME/caelestia-ai/usage.sqlite`；包括任务来源、次数、结果及接口返回的已知 token，未保存完整提示词或生成正文；翻译译文单独缓存，最多一万项。
- 状态/设置查询不返回真实密钥；输入框保存后清空。密钥仅在输入时短暂经过 UI 和 stdin，随后由 Python 后端读取，组件只拿状态和结果。
- 后端无监听端口、无 systemd 服务，不把凭据放参数、临时请求脚本或环境变量；API 密钥放 HTTP 认证头，拒绝重定向。
- 以上目录在仓库外，也在当前 Dotfiles 同步脚本清单外。未来扩大备份/同步范围时仍须排除凭据；同用户权限的恶意进程不在此隔离模型可防护的范围内。

## 任务接口

其他 QML 组件 `import qs.aibackend`，调用：

```qml
const id = Ai.request("generate", {
    source: "feature-name",
    system: "任务规则",
    messages: [{role: "user", content: "输入文本"}],
    maxTokens: 256
});
// Connections { target: Ai; function onCompleted(requestId, result) {...} }
// result: {ok:true,text,usage,status} 或 {ok:false,code,error}
// Ai.cancel(id) 取消排队/当前网络任务；由调用者处理过期回复。
```

后端 stdin 协议一请求一进程；QML 统一串行调度，队列最多16项。没有 UI 外的公开 IPC 生成端点，也没有把请求能力开放为桌面命令执行能力。
通用 generate 不自动缓存；业务自行选择缓存策略。模型查询只在明确操作时发生。

## 费用与失败保护

默认启用限额：每日100次、每分钟10次、单次最大输出512 token；每日/分钟计数在 SQLite 事务中预占，跨 Shell 重启保留。关闭“限制请求次数”后不再检查每日/每分钟次数，单次输出上限放到 16384（显式传入的 maxTokens 仍然生效），失败冷却与并发保护不变。模型查询、失败和已发出的取消请求均计数；缓存命中不计。日期按本机本地日期。
后端并发预占最多2个（正常 QML 串行只有1个），队列有界，输入总长上限32000字符。HTTP超时20秒，QML总任务看门狗45秒；不自动重试，网络/API失败后该服务冷却30秒。SIGTERM 尽力将当前计数标记取消。
取消本地请求无法撤销已到达服务商的请求或费用；硬杀/崩溃留下的pending预占最多50秒后不再阻塞并发。token统计不包含服务未返回的用量。
**本地请求上限不等于服务商消费硬限额**：大输入、模型价格、其他应用用量均会影响费用。需要严格金额上限时使用服务商的硬额度或独立低余额项目/密钥。

## 软件描述翻译

开启后由后台预翻译（`Translator` 单例）在空闲时批量补齐，软件页只读本地缓存，因此选中条目时通常已经是中文；未命中时才按需现场翻译（概览可见并停留600ms）。翻译提示词针对 Linux 语境保留 GNOME、KDE、Wayland 等专名；这不是准确率保证。
原文/软件名/服务地址绑定/模型/提示词版本共同确定缓存身份；模型或描述变化会重新翻译。页面切换取消旧任务，回复按请求ID隔离；失败保留原文，不循环重试，提供手动重试。悬停译文可查看原文。

## 后台预翻译

`Backend.py` 直接读取 `/var/lib/pacman/local/*/desc` 建立“已安装包 → 描述”索引（只读、不调用 pacman、不发网络），记录 `%REASON%` 区分显式安装与依赖，并为每行记录当前服务/模型下的缓存键。**只有显式安装（本机 434 个）进入预翻译队列**，依赖不预热——需要时在软件页选中按需翻译。待翻译队列按 `first_seen` 倒序，新安装或描述变化的包自然排在最前；连续解析失败或返回空正文 3 次的包会被跳过，直到描述再次变化。

调度在 QML 侧：`Translator.qml` 以低优先级（`Ai.request(..., "low")`）串行提交 `translateBatch`，用户在现场发起的翻译总是插到后台任务之前；软件页可见期间后台暂停开新批次（只收尾在途的一批），关闭后自动恢复；批间隔取 `60000 / minute × 1.2`，不占满每分钟额度。额度类错误（`daily_limit`/`rate_limit`/`cooldown`）静默退避，连续网络或解析失败 3 次停止本轮，等待下一次轮询（默认 2 分钟）或配置变化。Shell 启动、每 2 分钟轮询、AI 配置变化都会重新查询待翻译数量，因此新装的包无需重启也会被补上。

每批大小按 `outputTokens` 计算：`min(请求值, (outputTokens-256)/128)`，默认 8、上限 12；单批 `maxTokens = max(256, 128×条数)`。推理模型会先消耗输出预算再给出 JSON 正文，所以批量功能需要把“单次最大输出 token”调到 1024–2048；`512` 时每批只能 2 条，且可能整批返回空正文（后端会明确报“未返回正文”而不是静默失败）。批处理不改变每日/每分钟计数规则，缓存命中不计。

Nexus → AI 服务 显示“后台预翻译：待补 N 条 / 已全部完成”，并注明显式安装与全部已安装的数量。`CAELESTIA_PACMAN_DB` 可指向临时库用于测试，正式运行不需要设置。

## 软件页列表范围

软件页默认只列显式安装包（`filter="explicit"`），依赖通过“依赖”筛选查看；依赖的“可更新”“孤儿”仍在依赖视图内可查。搜索在显式范围内无结果时自动扩展到全部已安装，并在计数处标注“含依赖”，避免出现“明明装了却搜不到”。已缓存的依赖译文不会浪费，选中时直接显示中文。

## 部署与验证

`aibackend/` 是数据型外挂，`scripts/sync-addons.sh` 同步，无需 shell.qml 顶层实例；`Translator` 单例由 `console/Console.qml` 持有引用，Shell 启动即存在，不依赖是否打开过 Console。Nexus 两个注册表是底座，仅增加入口及导入，持久补丁 `patches/ai/nexus-ai-settings.patch`，升级脚本在原锁屏/布局补丁后应用；不反灌运行本体到仓库。

测试：`tests/ai/README.md`。本次仅用模拟接口及合成密钥验证，没有调用真实付费模型或读取已有用户密钥；系统密钥环服务存在，但真实用户凭据的写读流程仍待配置时验证。

参考本地 end-4/dots-hyprland 提交 `547836f`（2026-09-28）的 `services/ai/ApiStrategy.qml` 和 `services/KeyringStorage.qml` 的职责划分；本实现独立编写，不移植聊天记录、密钥打印、临时curl脚本或工具执行。

## 设置页结构

Nexus → AI 服务 主页：

- 概览：服务状态、当前模型、今日请求。
- 服务：启用开关；每个已配置服务一行（名称 · 默认 / 接口 · 模型），点行进入编辑页；“新建服务（接入新的供应商）”是同一张卡片里的最后一行，行高与其它行一致。
- 使用此后端的功能：每个使用 AI 的功能一行开关（当前为“软件描述翻译”），接入新功能直接加行。
- 用量与限额：一行“请求上限（每日 / 每分钟）”，点开子页；子页里先是一个“限制请求次数”开关，关闭后不限次数与单次输出，三个限额项随之隐藏。

子页只有两个：`AiServiceEditorPage` 编辑单个服务（名称、接口类型、Base URL、凭据存储、API Key、模型选择、保存/获取模型/测试、删除），新建与编辑共用，获取模型成功后模型列表直接展开；`AiUsagePage` 今日请求、限额开关与三个限额。主页通过 `AiUiState.editingId` 告诉编辑页打开哪个服务（空表示新建）。说明一律放字段 subtext，不写整段文字，不展示预翻译队列等内部状态。

Nexus → AI 服务 按“概览 → 使用方式 → 服务 → 编辑 → 功能 → 用量与限额”组织：顶部概览显示启用状态、当前服务与模型、今日请求；三步使用指引说明新建服务、获取模型、开启功能的顺序；服务列表每行可直接进入编辑，只有未配置服务时才自动展开新建表单；编辑区拆成“连接”（名称/类型/地址/存储/密钥）与“模型”（发现的模型/模型 ID/保存后获取）两组，保存、获取模型、测试模型、取消与删除都留在同一处；限额与按来源用量收进默认折叠的“高级设置”。只有多个服务时才显示“默认服务”下拉。


### 2026-10-21 设置视觉组织
主页按“当前连接 / 服务连接 / 接入功能”组织，默认模型与用量入口归到当前连接，消除重复状态。编辑页按连接、凭据、模型分组，名称/URL/Key共用一条输入列；模型池与刷新开关/测试共用一组ConnectedRect，使用单选标记、浅主色选中态和统一Text操作，保存和危险删除分开。用量页使用一致的标题和标签。只调整三个QML页，不改后端、模型/密钥、限额或预翻译行为。
截图工具增加 --theme（读取当前色板快照）、--native（私有数据的Wayland测试窗口）、--compact（720px宽）。预览使用模拟服务和私有XDG，不代表真实用户配置。
